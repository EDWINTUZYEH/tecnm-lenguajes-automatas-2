Sistema de Tipos Primitivos y Verificación Semántica

¿Cómo decide el compilador si una operación entre dos tipos tiene sentido?

Objetivo de hoy

Aplicar una tabla de compatibilidad de tipos y explicar por qué asignar un tipo más ancho a uno más angosto exige una conversión explícita.

Al terminar tendrás

Una tabla de compatibilidad en C que acepta asignaciones seguras, rechaza las que pierden datos y nombra cada tipo.

Antes de los tecnicismos: los conceptos básicos

Si te quedas con estas ideas, el resto de la sesión se entiende solo.

01. Tipo

La etiqueta que dice qué clase de valor es algo y qué operaciones admite.

Analogía: Como el género en una biblioteca: no es el libro, pero dice dónde va y cómo se usa.

02. Compatibilidad

Regla que dice si un valor de un tipo puede usarse donde se espera otro.

Analogía: Como un adaptador de enchufe: si no encaja, o usas adaptador o no hay corriente.

03. Ensanchamiento y estrechamiento

Pasar a un tipo que guarda más información (seguro) o menos (con pérdida).

Analogía: Como vaciar una cubeta en un vaso: cabe, pero algo se derrama.

04. Tipo centinela

Un tipo especial que marca un nodo inválido para no encadenar falsos errores.

Analogía: Como una ficha roja en un inventario: dice este no cuenta y evita seguir contando mal.

¿Dónde estamos y a dónde vamos?

La sintaxis acepta x = y con cualquier cosa; la semántica decide si esos tipos pueden convivir. Esa decisión evita que el programa genere instrucciones imposibles, como sumar una estructura con un número.

00–20 min: Fundamentos teóricos — El Rol del Analizador Semántico

La sintaxis valida que la estructura sea legal; la semántica valida que las operaciones tengan sentido lógico y de tipos.

01. Tipado Estático vs Dinámico[+]

En compiladores estáticos, cada variable y expresión tiene un tipo determinado en tiempo de compilación.

Previene errores de ejecución antes de generar una sola instrucción binaria.
02. Tabla de Compatibilidad[+]

Una matriz booleana que define qué tipos pueden operar entre sí (ej. int + int -> int, int + float -> float).

Determina si una operación es legal, requiere conversión o es un error semántico.
03. Equivalencia de Tipos[+]

Equivalencia nominal (mismo nombre de tipo) vs estructural (misma disposición de bytes interna).

C utiliza equivalencia nominal para struct y estructural para tipos básicos vía typedef.

Arquitectura de memoria y estructuras de datos: Atributos Sintetizados de Tipo en el AST

Decoración del árbol con información de tipo durante el postorden:

Propagación Ascendente[+]

El tipo de un nodo operador se sintetiza a partir de los tipos ya validados de sus dos ramas hijas.

Si izq->tipo == INT y der->tipo == INT, el nodo actual sintetiza tipo = INT.
Tipo ERROR_TYPE[+]

Tipo centinela especial asignado a nodos inválidos para evitar que un solo error dispare una cascada de falsas alertas.

El analizador semántico reporta el primer error y propaga el centinela.

Errores Semánticos Típicos

Puntos críticos de falla que debes proteger en tu código y auditar en las respuestas del LLM:

  • Asignación de tipos incompatibles: Asignar un puntero a una variable entera sin casteo explícito.
  • Operadores incompatibles: Intentar aplicar operaciones aritméticas a estructuras o cadenas.
  • Cascada infinita de errores por no usar un tipo centinela al detectar el primer fallo.
